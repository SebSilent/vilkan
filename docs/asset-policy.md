# Asset policy (rule #1)

**Nothing from the game is ever stored in this repository.** Everything is
built on the user's machine from files the user supplies. The same applies
to other titles used for testing, and to any other proprietary material.

## Not allowed

In any form (files, string literals, fixtures, snapshots, docs):

* assets: models, textures, shaders, audio, video, text, archives;
* the executable or any part of it: data sections, strings, tables,
  resources, code beyond the signatures below;
* anything derived from those: converted assets, decompiled or
  disassembled code, shader dumps, extracted tables, screenshots.

## Allowed

* our own code that understands formats;
* small interoperability constants (magic numbers, enum values) we write;
* synthetic test data generated by our own code.

Build identities, per-build hook offsets and byte-pattern signatures for a
specific title are **not** kept in the public tree: they are title-derived
and live with the user's data outside the repository.

The BCPack decode tables are a mix: the rANS models and rank tables are codec
constants, but the BC6H/BC7 built-in history is calibrated from the user's
title data. The whole table file is therefore treated as game-derived and
kept **outside** the tree (`VILKAN_BCPACK_TABLES`, or `bcpack-tables.bin`
under `VILKAN_SHADER_FIXTURES`); `Tables::builtin` loads it at run time and
the tests skip when it is absent.

## No exceptions

The policy allowlist has **zero exceptions**. Anything that cannot pass it
(binary assets, captured shaders, title-specific dumps) stays outside the
tree, in the external data dir, untracked.

## Where data lives

Outside the repository, configured in `vilkan.toml`: `game_dir` (the
user's dump), `test_titles`, and `cache_dir` for everything derived
(default `%LOCALAPPDATA%\vilkan\cache`).

## Enforcement

1. `.gitignore` keeps common data types out of `git status`.
2. `cargo xtask policy` (run by the pre-commit hook; install with
   `cargo xtask install-hooks`) is an allowlist with **no exceptions**:
   files must have an allowed type, be under 512 KiB, contain no binary
   data or known binary signatures, and hold no long hex/base64 runs.
3. At runtime, everything that writes derived data calls
   `vilkan_core::ensure_outside_repo`.
4. Tests that need real files take their paths from environment variables
   and skip when unset. They assert on properties, never on snapshots.

## If something slips through

The public repository is **initialized fresh from a scrubbed tree**, never
pushed from this fork's history (see the README). So a leak in the working
history does not reach the public repo: re-scrub the tree and re-initialize.
Do not push this fork's history anywhere public.
